# v0.2.3-rc1 Release Candidate

Status: release candidate
Product version: v0.2.3-rc1
Package version: 0.2.3-rc.1
Scope: Safe Mutation closure, version hygiene, and acceptance audit

This release candidate closes the first Safe Mutation pass. It does not add a new product workflow. Its purpose is to make the v0.2.1 Semantic Foundation, v0.2.2 Relationship Stability, and v0.2.3 Safe Mutation work clear enough to review, stage, and either ship or park intentionally.

## Included Source Changes

- Semantic status helpers under `src/domain/semantics`.
- Central relationship graph helpers under `src/domain/relationships`.
- Central mutation helpers under `src/domain/mutations`.
- App-level thought/project mutations now route through the domain mutation layer.
- AI patch application is limited to descriptive fields and cannot directly mutate status, readiness, lifecycle status, IDs, timestamps, or relationships.
- Delete and detach flows now use shared stale-reference cleanup.
- Import normalization repairs resolvable relationship endpoint types while preserving orphan relationships for warning-capable views.
- Safe Mutation policy is documented in `docs/safe-mutation-policy.md`.

## Dirty And Generated Audit

The workspace still contains pre-existing or generated dirty files. This RC records the classification without deleting or reverting anything.

| Path group | Classification | RC action |
| --- | --- | --- |

`.gitignore` now includes standard local dependency, build, Playwright, coverage, and TypeScript cache patterns. Existing tracked generated files remain tracked until a human intentionally removes them from version control.

## Safe Mutation Acceptance Checklist

| Area | Expected guardrail | Evidence |
| --- | --- | --- |
| Thought create/update/archive/restore/delete | Primary thought mutations have a domain owner and delete cleans relationships plus stale references. | `src/domain/mutations/appMutations.ts`, `src/domain/mutations/referenceCleanup.ts`, `src/domain/mutations/appMutations.test.ts` |
| Project create/update/archive/restore/delete | Primary project mutations have a domain owner and delete cleans linked thought, relationship, AI insight, and next-action references. | `src/domain/mutations/appMutations.ts`, `src/domain/mutations/referenceCleanup.ts`, `src/domain/mutations/appMutations.test.ts` |
| Universe delete/detach/block-if-in-use | In-use deletion is blocked by default; detach mode clears universe references and relationships. | `src/domain/universeActions.ts`, `src/domain/universeActions.test.ts` |
| Blocking question delete/resolve/archive | Delete clears relationships and downstream decision source references; accepted decisions can resolve their source question. | `src/domain/blockingQuestions.ts`, `src/domain/blockingQuestions.test.ts`, `src/domain/decisionRecords.ts`, `src/domain/decisionRecords.test.ts` |
| Decision accept/delete/supersede | Accept can resolve source blocking questions; delete clears supersede references and relationship edges. | `src/domain/decisionRecords.ts`, `src/domain/decisionRecords.test.ts` |
| AI patch apply | AI can update descriptive fields only and cannot directly mutate lifecycle/status/readiness or identity fields. | `src/domain/mutations/aiPatchMutations.ts`, `src/services/applyAiPatch.test.ts` |
| Import normalize | Legacy relationship endpoint types are repaired when endpoints resolve; orphan relationships are preserved for reporting. | `src/domain/appState.ts`, `src/services/appStateTransfer.test.ts` |
| Relationship cleanup | Deletions use typed relationship helpers instead of scattered relationship filtering. | `src/domain/relationships/relationshipGraph.ts`, `src/domain/mutations/referenceCleanup.ts` |
| NextAction reference cleanup | Deleted nodes are removed from focus, saved, and dismissed next-action references. | `src/domain/mutations/referenceCleanup.ts`, `src/domain/mutations/appMutations.test.ts` |
| AIInsight target cleanup | Deleted node targets are removed from AI insights. | `src/domain/mutations/referenceCleanup.ts`, `src/domain/mutations/appMutations.test.ts` |
